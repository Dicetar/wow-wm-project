# 12 - Preview shared-world changes with dependency evidence

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

Before changing an existing encounter or spawn group, WM shows a concrete impact plan with reasons, affected gameplay, replacement or restoration steps, and unsupported dependencies.

## Acceptance criteria

- [ ] Introduce a bounded continuity plan through existing plan/preview infrastructure, identifying specific affected entities, provenance, revision, duration, and cause.
- [ ] Inspect objective and start/end relations, prerequisite chains, relevant drops/services, live and offline player progress, and supported event/script dependencies.
- [ ] Begin with one precisely defined spawn-group/quest operation family; report coverage and unresolved references instead of claiming a universal dependency graph.
- [ ] Require a realizable replacement, transition, or defined temporary interruption/restoration for affected gameplay; narrative justification alone cannot pass preview.
- [ ] Use capability classification for each planned step, including failure/retirement semantics and recovery; unknown affected dependencies block that plan and can emit a development request.
- [ ] Expose a readable impact summary and exact execution dependencies in the panel without exposing raw mutation controls.
- [ ] Record before-state and revision assumptions for later conditional apply; tests cover accepted/rewarded/offline quest state and dependency changes after preview.

## Blocked by

- [Report which requested capabilities can actually run](https://github.com/Dicetar/wow-wm-project/issues/8)
- [Base WM decisions on fresh environment evidence](https://github.com/Dicetar/wow-wm-project/issues/11)

## Verification and scope

Repo/DB-fixture/API preview proof with no live destructive change. Execution is deliberately a separate bounded lifecycle ticket.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
