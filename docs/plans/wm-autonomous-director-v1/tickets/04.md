# 04 - Manage persistent World and Character Author's Notes

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

The operator creates, edits, disables, and removes Author's Notes in a dedicated panel view; notes survive restart and retain their intended World or Character scope.

## Acceptance criteria

- [ ] Extend existing durable conversation steering with explicit Author's Note provenance, scope, original wording, normalized direction, active state, revision/history, and optional expiration.
- [ ] Preserve current character memories during migration and keep explicit direction separate from inferred facts and observed events.
- [ ] Provide usable note CRUD and scope selection through the existing panel API/UI, with validation, error states, and durable readback.
- [ ] Ordinary notes are preferences. Firm constraints are optional advanced metadata, with specific preferences overriding broader preferences but not firm constraints.
- [ ] Return applicable notes and unresolved firm-constraint conflicts through one reusable retrieval interface for planners; do not silently overwrite contradictory records.
- [ ] Demonstrate two character identities and a World note with no accidental character-note leakage; expired/disabled notes no longer guide planning.
- [ ] Cover edit races and revisions, migration, restart, and panel browser smoke using existing memory and API test boundaries.

## Blocked by

None - can start immediately.

## Verification and scope

Repo/API persistence and browser proof. In-game automatic capture and broad planning integration are delivered by the natural-language ticket.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
