# 07 - Apply On Demand, Moderate, and Active initiative presets

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

The operator changes WM initiative in the panel, and the same recorded play events produce the expected amount of unsolicited activity without suspending active content.

## Acceptance criteria

- [ ] Persist On Demand, Moderate, and Active with Moderate as default and expose selection through existing session controls.
- [ ] Separate unsolicited opportunity creation from direct requests, active-story progression, accepted-quest handling, promised consequences, and cleanup.
- [ ] On Demand suppresses new unrequested experiences while all ongoing obligations and observation continue.
- [ ] Moderate selects meaningful opportunities without crowding unresolved content; Active increases opportunity-seeking within configurable budgets while preserving relevance.
- [ ] Use fresh context, stable event IDs, persistent cooldowns/backlog state, and finite generation attempts; self-generated events and duplicate native delivery cannot cause feedback loops.
- [ ] Keep preset pacing distinct from capability authorization, content validation, and world continuity.
- [ ] Honor explicit temporary quiet periods supplied by the request interface when available, while keeping cleanup active.
- [ ] Replay one identical event stream under all presets and after restart, checking decisions and suppression reasons rather than exact prose; verify panel selection and live pacing.

## Blocked by

- [Recover one WM request through restart and native completion](https://github.com/Dicetar/wow-wm-project/issues/7)
- [Base WM decisions on fresh environment evidence](https://github.com/Dicetar/wow-wm-project/issues/11)

## Verification and scope

Deterministic replay/API/browser proof and preset-specific live evidence. Tuning values are documented configuration, not a new user interview blocker.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
