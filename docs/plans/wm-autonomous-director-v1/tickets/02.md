# 02 - Recover one WM request through restart and native completion

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

A selected character's low-risk request has one durable identity and an honest result in the panel and game, including when the panel/autoplay restarts or the native reply arrives late.

## Acceptance criteria

- [ ] Use an existing supported low-risk action to prove received -> preview -> apply -> native terminal result -> observable outcome; keep submitted, executed, and verified states distinct.
- [ ] Persist source identity, selected marker provenance, plan revision, operation progress, native references, and failure/recovery detail using existing durable state infrastructure.
- [ ] Deduplicate repeated delivery of the same originating command/event, including channel mirrors and restart, without deduplicating a genuinely new identical command.
- [ ] Handle non-throwing failure results, native timeout/late failure, and crash after submit without treating a generic applied envelope as verified success.
- [ ] Revalidate session/target and relevant plan revisions at execution time; changing the selected character cannot redirect old work.
- [ ] Unify the panel's view of durable pending/issues/results with autoplay records rather than making another process-local queue.
- [ ] Show recoverable pending and terminal outcomes through existing session APIs/UI; retry reconciles receipts before dispatch.
- [ ] Add high-level failure-injection tests across each side-effect boundary and one scoped native result proof when BridgeLab is available.

## Blocked by

None - can start immediately.

## Verification and scope

Repo/API recovery behavior plus native terminal-result proof. This is the common result contract used by later tickets; it need not rebuild every publisher in this slice.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
