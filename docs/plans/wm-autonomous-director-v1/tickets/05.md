# 05 - Route natural-language requests and remember standing direction

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

The player can ask for a supported task or state a standing preference in ordinary language; WM routes the request correctly, saves notes when appropriate, and reports a durable outcome.

## Acceptance criteria

- [ ] Route input into a typed task, Author's Note change, explicitly temporary instruction, conversational answer, or material clarification; retain the user's original wording.
- [ ] Default in-game notes to the authenticated speaking character; explicit World direction requires the configured operator authority, not a model-asserted identity.
- [ ] Persist standing requests such as 'give me fewer quests'; keep 'leave me alone while I farm' temporary and represent its ending condition.
- [ ] Retrieve relevant World and Character notes for task planning and content drafting, not chat wording alone; capture used note revisions in the plan.
- [ ] Handle explicit changes and conflicting firm constraints without repeatedly confirming routine authorized commands; ask only where meaning affects the result.
- [ ] Use capability classification to report unsupported or maintenance-bound content accurately and emit typed development-request candidates.
- [ ] Revalidate note changes and target changes before pending work executes; apply the durable request identity and outcome contract.
- [ ] Test representative phrasing and typos, cross-character conversations, temporary versus standing instructions, conflicting notes, duplicate inputs, and restart.

## Verification and scope

Replay/API routing plus live conversation and note-retrieval proof. Content-specific execution is completed by the quest and spell tickets.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
