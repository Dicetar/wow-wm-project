# 08 - File missing-mechanic development requests automatically

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

A genuine capability gap becomes one useful GitHub issue, visible in the panel, and deferred content can be reconsidered once the implemented capability is deployed and verified.

## Acceptance criteria

- [ ] Consume typed capability-gap records from existing blocked/deferred work and persist an outbound delivery record before attempting GitHub.
- [ ] Create issues automatically in the configured repository with intent, minimal relevant context, capability evidence, examples, acceptance criteria, known client/server requirements, and deferred-work references.
- [ ] Deduplicate by capability gap and compatible requested semantics; preserve additional useful cases without creating issue spam. Apply configurable creation/update rate limits.
- [ ] Remove secrets and irrelevant personal/account/chat data; do not permit model-chosen repository destinations or arbitrary commands.
- [ ] Handle offline/auth/rate-limit failure and ambiguous successful responses with durable retry/reconciliation, including process restart without duplicate remote issues.
- [ ] Show delivery status, issue link, remote status, and affected deferred requests in the panel. Issue closure is not a capability-ready signal.
- [ ] On a verified deployed capability revision, re-evaluate deferred work against current notes, request expiry, target, and world; do not replay obsolete intent blindly.
- [ ] Distinguish missing capability from service outage and maintenance so those conditions do not generate misleading development tasks.
- [ ] Test the full gap-to-issue lifecycle with a fake remote adapter and one clearly labelled real issue exercise, reconciling the exercise afterward.

## Blocked by

- [Recover one WM request through restart and native completion](https://github.com/Dicetar/wow-wm-project/issues/7)
- [Report which requested capabilities can actually run](https://github.com/Dicetar/wow-wm-project/issues/8)

## Verification and scope

Repo/API/outbound integration proof. The current user explicitly authorizes automatic development issue creation; routine publication needs no additional confirmation.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
