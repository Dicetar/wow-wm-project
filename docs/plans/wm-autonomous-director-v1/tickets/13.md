# 13 - Run and restore a temporary world event without stranding quests

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

WM temporarily transforms one existing encounter for a justified event, gives affected players a coherent quest path, and restores it correctly even after interruption.

## Acceptance criteria

- [ ] Execute the validated bounded continuity plan through owned typed operations and the existing action bus, not freeform SQL or an unscoped admin escape hatch.
- [ ] Prepare and verify replacement quest/actor paths before suspending originals; preserve concrete source records, affected players, receipts, and expiry.
- [ ] Recheck impact/revisions at apply time and serialize overlapping changes to the same entities; a stale preview cannot overwrite newer content.
- [ ] Handle partial failure with durable compensation or a visible recovery task; no successful-looking state may leave an impossible objective.
- [ ] Restore only WM-owned changes at expiry or recovery, including expiry while services are stopped; respect conflicting later edits.
- [ ] Keep restoration and existing quest progression functioning under On Demand and generation outages.
- [ ] Explain the event and continuation to affected players; avoid duplicate progress/rewards across reconnect or retries.
- [ ] Demonstrate the event, replacement quest path, expiry, restart recovery, and rollback with in-client evidence in a controlled live area.

## Blocked by

- [Generate and deliver a feasible quest from actual play](https://github.com/Dicetar/wow-wm-project/issues/14)
- [Preview shared-world changes with dependency evidence](https://github.com/Dicetar/wow-wm-project/issues/17)

## Verification and scope

Failure-injection integration tests plus live temporary world-continuity and restoration proof. Scope may include existing world content, but only the supported operation family.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
