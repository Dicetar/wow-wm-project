# 09 - Generate and deliver a feasible quest from actual play

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

A direct request or relevant autonomous opportunity produces a fresh compiler-authored quest that the selected character can accept, complete, and turn in for the displayed reward.

## Acceptance criteria

- [ ] Use the existing compiler and owned publishers; ship exactly the validated plan rather than manually cloning or editing a live quest afterward.
- [ ] Resolve targets and start/end actors from current facts: attackability, level, actual availability, phase/access, objective count, prerequisites, and reachable turn-in path.
- [ ] Reject too few suitable spawns, friendly/untargetable objectives, unavailable drops/actors, and stale facts; account for respawn requirements when an objective depends on them.
- [ ] Put actionable directions in the objective summary, narrative in description, and validate all required reward/actor/model/credit fields.
- [ ] Read applicable Author's Notes and preset opportunity decisions; avoid unsolicited duplicates or a flood of active quests.
- [ ] Keep reservation/preview/apply identity stable; revalidate volatile facts, read back published rows, synchronize runtime, and grant/reward once.
- [ ] Exercise publication, acceptance, completion, display, reward delivery, and cleanup through public paths using a fresh canonical marker-selected character.
- [ ] Add regression cases for the previous hostile-target, insufficient-spawn, missing-actor, reward-panel, and stale-content failures; mark in-client proof separately.

## Blocked by

- [Route natural-language requests and remember standing direction](https://github.com/Dicetar/wow-wm-project/issues/10)
- [Apply On Demand, Moderate, and Active initiative presets](https://github.com/Dicetar/wow-wm-project/issues/12)

## Verification and scope

Compiler/publisher tests plus full in-client quest lifecycle. This closes the existing ADR-0004 proof requirement as part of useful generated content.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
