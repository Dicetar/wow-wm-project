# 10 - Compose functioning spells from reusable tested mechanics

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

WM turns a supported spell request into parameterized, character-independent runtime behavior, with a visible shell whose effect matches the request.

## Acceptance criteria

- [ ] Extend the existing ability schema/compiler and native shell runtime with a bounded composition model; do not create a second spell engine or arbitrary script VM.
- [ ] First prove an active self-buff and a passive on-hit composition with timed periodic damage; prove a second supported combination or parameterization changes real gameplay rather than name alone.
- [ ] Bind every accepted primitive and parameter to actual native/DBC behavior, including target filters, costs where applicable, duration, scaling, proc chance, cooldown, and lifecycle cleanup.
- [ ] Validate unsupported combinations, cyclic proc behavior, invalid references/values, and missing behavior bindings before a grant can claim success.
- [ ] Expose the exact supported vocabulary and evidence through the capability view. A registered schema branch or applied marker does not prove implementation.
- [ ] Use fresh managed test shells with matching visible presentation and preserve existing character-specific mechanics and unrelated aura state.
- [ ] Prove behavior and revocation for two different selected character identities, with actual combat/effect checks and native regression tests.
- [ ] Keep new client payloads visibly pending until deployment is verified; the following deployment ticket closes the full newly generated identity workflow.

## Blocked by

- [Route natural-language requests and remember standing direction](https://github.com/Dicetar/wow-wm-project/issues/10)

## Verification and scope

Native build/tests, compiler tests, and live mechanical proof using verified shell payloads. This ticket develops missing reusable machinery; WM itself does not write native code.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
