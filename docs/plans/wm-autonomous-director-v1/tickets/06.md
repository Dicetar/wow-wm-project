# 06 - Base WM decisions on fresh environment evidence

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

WM describes and plans against the selected character's actual surroundings, fetching more detail when needed and explaining when its information is missing or stale.

## Acceptance criteria

- [ ] Build on existing native presence/perception/snapshots and context packs; include observation time and map/instance/phase relevance for facts used by decisions.
- [ ] Replace Online-only freshness assumptions with timestamp and world-identity checks; reject missing, expired, inconsistent, or future-dated evidence according to a documented bounded policy.
- [ ] Request a targeted native snapshot through the existing bus when counts or stale summaries cannot answer an action-relevant question.
- [ ] Expose actor identity, live availability, and player-relative attackability where a decision needs them; a faction-ID blacklist is not sufficient evidence.
- [ ] Preserve offline historical memory as historical; do not present old positions or actors as currently observed.
- [ ] Show the observation basis or blocker in session/API status and use the same evidence for chat and opportunity planning.
- [ ] Test movement between maps/instances, stale online rows, wrong target, empty perception, snapshot timeout, and nearby friendly/hostile actors; record one live observation proof.

## Blocked by

None - can start immediately.

## Verification and scope

Repo/native/API evidence plus live surroundings proof. Extend only sensors needed by these decisions, not a speculative full-world sensing framework.

Use the existing WM workflow and relevant native/content skills. Preserve the Python/native ownership split, typed gates, current marker targeting, and unrelated working-tree changes. This is a complete user-visible or publicly verifiable slice; tests should exercise outcomes rather than source layout.
