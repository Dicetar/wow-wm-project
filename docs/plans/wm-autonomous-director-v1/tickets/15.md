# 15 - Prove the Autonomous Director release through full play sessions

## Parent

[WM Autonomous Director V1](https://github.com/Dicetar/wow-wm-project/issues/5)

## What to build

The operator has a reproducible release demonstration showing the agreed WM behavior during ordinary play, including failures and recovery, with trustworthy panel and gameplay status.

## Acceptance criteria

- [ ] Extend the existing replay runner to drive real session/orchestration and persistent-note retrieval; canned replies and fabricated memory references alone do not satisfy the gate.
- [ ] Cover natural-language requests, fresh observations, all initiative presets, Author's Notes scopes/conflicts, development issues, generated quest/spell lifecycles, and temporary/lasting world continuity.
- [ ] Run the configured 30-minute sample for each preset over at least two selected character identities, recording event/input corpus, model/runtime versions, configured timing budgets, and observed results.
- [ ] Include duplicate input, one service interruption/restart, delayed native failure, changed notes, offline player, and a maintenance-bound spell; prove bounded recovery and honest status.
- [ ] Require no duplicate grants, cross-scope execution, unhandled quest stranding, false completion, or unresolved release-blocking defects; fix discovered defects before promotion.
- [ ] Verify desktop/mobile panel layouts and primary operator flows, including pending work, reasons for silence, development issue links, maintenance, and recovery.
- [ ] Run the unfiltered full suite and required native/build checks from the actual tracked release candidate. Report manual/live exclusions explicitly rather than treating them as passes.
- [ ] Attach canonical marker provenance, artifact revisions, native receipts, client/server deployment evidence, and player-visible observations to the release proof.
- [ ] Update current release/status docs only to the level established by evidence; retain PARTIAL for missing proof and link exact blockers.
